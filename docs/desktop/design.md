# 桌面宿主架构

## 边界

- `web/`：唯一研究界面和 API 客户端。
- `server/`：唯一实验、对局、评估、比较、结论实现。
- `server/desktop_entry.py`：设置应用数据路径，装配静态前端与本机会话，启动同一个 FastAPI 应用。
- `desktop/`：单实例窗口、启动页、后端进程所有权、错误展示与多窗口关闭协调。
- `scripts/desktop/`：可重复的构建与隔离验收入口。

## 启动契约

宿主启动随安装包提供的后端，并通过参数传入数据目录。后端预绑定 `127.0.0.1:0`，由操作系统分配端口，避免固定端口冲突与“查询空闲端口再启动”的竞争。FastAPI lifespan 完成后，通过私有 stdout 管道输出一条当前结构的 JSON readiness 消息。其余日志写 stderr，落入应用日志文件。

宿主等待最多60秒。一次性启动票据换取 HttpOnly、SameSite=Strict 的进程会话 cookie 后，导航到 `/`。不将票据写入应用日志；票据不可再次使用。每个进程生成独立 cookie 名，避免不同端口共享 cookie 名造成覆盖。HTTP 与 WebSocket 均校验 Host、会话；携带 Origin 的请求必须同源，WebSocket 必须携带同源 Origin。该机制不声称隔离同一用户下的恶意本机程序。

后端同时提供构建后的前端，因此 HTTP、WebSocket 和文件导出复用现有路径。未知 API 与缺失静态文件保持404，只有页面路由回到 index.html。远程页面不获得 Tauri 原生权限；没有通用 shell 或文件读写桥接接口。

本次后端就绪后，宿主仅为其精确回环源（含随机端口）添加生命周期能力，适用于 main 与 evidence-* 窗口。build.rs 注册 complete_close、cancel_close 两个应用命令权限；另允许事件订阅/取消订阅。页面不能直接退出应用、停止进程或执行文件/shell操作。命令使用实际调用窗口身份校验源、请求号和参与成员，不接收前端声称的窗口名称。

## 进程生命周期

宿主持有后端 stdin；退出关闭管道，请求后端优雅结束，最多等待7秒后终止。Windows Job Object 使用 KILL_ON_JOB_CLOSE，在宿主异常结束时清理所管理的进程树。应用不接管用户独立启动的模型服务。服务异常退出不会自动重启并重复执行任务，而是提示用户重开检查中断状态。

已有启动恢复会标记未完成任务，并不等于恢复其执行状态。本批不新增恢复算法。所有研究动作仍由用户通过现有业务接口明确发起。

### 退出前保存

关闭主窗口或收到普通应用退出请求时，Coordinator 为所有研究窗口建立单次请求；关闭证据窗口只包含自身。宿主发送定向的 cardlab-close-requested 事件，前端监听明确限定为当前 WebviewWindow，不能使用全局事件订阅代替窗口订阅。

Vue 的 DesktopLifecycle 锁定交互与路由并调用既有草稿 store.flushAll。保存成功且没有未创建的 Prompt A/B 设计时回复 saved；冲突/写入失败或未完成设计取消本次关闭并保留输入。异步编辑在确认后产生新修改也会撤销关闭准备。取消后各窗口解锁，迟到回复不能影响新请求。

全部窗口成功后，主窗口才显示原生退出确认，明确提示停止服务和中断任务；证据窗口则独立销毁。45秒未完成准备时取消关闭，不能用超时代表成功；最终用户确认没有自动同意期限。等待期间拒绝新的原生导航或证据窗口。启动页尚无编辑会话，可直接进入原生退出确认。

这套保护覆盖已接入持久草稿的研究编辑器和注册为阻止项的 Prompt A/B 向导，不会将未提交的其他普通创建表单自动持久化。系统强制结束、异常断电和后端崩溃不属于正常关闭握手，不能保证尚未确认的输入。详见 [第五批 A](../../specs/desktop-research-workspace/batch-5a.md)。

## 当前结构与维护

宿主、后端、前端作为同一安装包构建发布。不寻找本机 Python、不连接固定端口上的未知服务、不回退到源码运行、不读取项目 `.env`，也不转换历史 API 结构。环境变量 `CARDLAB_ENV_FILE` 只选择当前配置来源；桌面入口将其指向应用数据目录的 config.env（文件可不存在），浏览器开发仍使用项目配置。

启动页仅表达等待或错误，使用平台字体、现有中性色与清晰的状态文本。进入工作台后继续使用现有 Vue 设计系统。

同源证据链接在共享 WebView 会话的独立窗口中打开，避免丢失主窗口结论草稿；关闭证据窗口不退出整个应用。

## 主窗口研究位置恢复

主窗口在工作台挂载前读取应用数据目录的 `workspace.json`。恢复的是相对路由，不包含端口或会话票据；路由元数据 `desktopResume` 声明允许恢复的查询参数。研究、运行、比较和决策审查复用当前 URL 的定位能力，创建表单触发参数不保存。非首页的显式打开或刷新保留自己的地址。

导航更新内存中的最后研究位置，正常关闭准备阶段写入并确认；进入设置等非恢复页面不替换已记录的研究位置，回研究首页则明确记录首页。记录写入使用同目录临时文件、文件同步和替换，失败取消关闭。它不提供每次导航落盘或异常断电保证。

`read_workspace` / `save_workspace` 仅授予当前精确后端源的主窗口，并在命令内复查源与窗口身份。调用者不能指定文件路径；证据窗口既不恢复也不写主窗口记录。读取限制为 8 KiB，记录只接受当前结构，非法或损坏记录显示提示并继续使用；不增加历史格式转换。

草稿仍由 SQLite 和唯一草稿服务负责。恢复位置不复制业务数据、不恢复任务执行、不自动重开证据窗口或未提交向导。关闭准备后若迟到导航完成，会撤销保存确认。范围见 [第五批 B](../../specs/desktop-research-workspace/batch-5b.md)。

第五批 E 将主窗口布局纳入同一记录：`workspace.json` 的 `route` 和必需的 `window` 一起校验、序列化并原子替换。布局字段为普通矩形的 left/top/right/bottom 及 maximized；页面不传入窗口坐标。`read_workspace` 读出完整记录后先恢复布局，再返回相对路由；显式地址刷新仍保留自己的页面和窗口。

`window_layout.rs` 复用 Windows 的 GetWindowPlacement / SetWindowPlacement 成对采集恢复，不与屏幕坐标混用；普通矩形在最大化时仍保留，最小化转换为普通或最大化启动状态。Windows 会调整完全离屏的位置，见 [SetWindowPlacement](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowplacement)。布局及路由只接受当前完整结构，未知字段、缺失布局和非法矩形返回恢复失败，不做格式转换或另设布局文件。详见 [第五批 E](../../specs/desktop-research-workspace/batch-5e.md)。

## JSON 与 HTML 文件导出

研究结论、比较快照、实验包、选手配置与草稿副本共用 `downloadJson` 序列化；可读报告 HTML 与 JSON 共用 `downloadText` 传输。桌面调用唯一 `save_export` 命令，使用当前窗口为父窗口的系统另存为对话框；浏览器交付下载。取消不产生成功提示，桌面失败不回退到浏览器下载。

原生命令校验研究源、建议文件名、固定的 JSON/HTML 格式与 32 MiB UTF-8 上限；JSON 另行检查语法，HTML 由报告正文生成。它不接收目标路径，实际位置仅来自系统对话框，并校验扩展名与所选格式一致。命令只授予当前研究源的 main/evidence-*，不授予通用文件、shell 或系统对话框 IPC 权限。阻塞对话框和磁盘写入在工作线程执行。

导出占用与关闭请求由同一个 Coordinator 互斥管理；导出期间不进入关闭准备或销毁窗口，关闭期间不开始导出，取消/错误释放占用。`file_io::replace_file` 使用同目录唯一临时文件、文件同步和替换；位置记录也调用此唯一写入函数。成功只表示本次文件写入确认，不保证断电后的物理介质持久性。

导出内容和敏感字段筛选仍属于原业务服务。可读报告与独立 HTML 使用同一 Vue 正文；HTML 移除应用内跳转，仅保留页内锚点，无脚本和外部资源依赖。它不是完整复现包或大型训练数据导出，范围见 [第四批 A](../../specs/desktop-research-workspace/batch-4a.md)。

## 保存后定位文件

保存完成后返回记录编号，取消返回 null。`SavedExports` 按窗口保存最近一条编号及目标路径，仅驻留宿主内存；后续成功保存替换记录，取消/错误不覆盖，窗口销毁清理。前端不获得路径，也不维护文件历史或旧返回格式分支。

`reveal_saved_export` 校验精确研究源、调用窗口和记录编号，在工作线程检查文件仍存在并通过既有 `windows-sys` 调用 `SHOpenFolderAndSelectItems`。按 Windows 的单项契约传入文件的完整 PIDL、`cidl = 0` 和空选择数组，打开父目录并选中文件；配对 COM 初始化/释放和 PIDL 释放，系统失败明确返回错误。没有 opener 插件、通用前端命令或失败回退，也不启动文件关联程序。定位与保存共用 Coordinator 占用，关闭准备期间拒绝新操作。API 语义见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenfolderandselectitems)。

共用导出入口将编号绑定到现有成功 Toast 的操作。每个窗口只保留一个导出成功提示；操作期间禁用按钮，成功关闭提示，失败保留重试并独立说明定位失败。取消和浏览器下载不产生原生定位入口。范围见 [第五批 D](../../specs/desktop-research-workspace/batch-5d.md)。
