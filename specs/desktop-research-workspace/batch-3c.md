# 第三批 C：冻结比较内的场景导航

2026-11-07，执行已授权的 R4、R5、R10，延续现有比较与引用工作区。

## 验收条件

- 双组斗地主快照支持按既有互斥场景分类选择共同有效发牌，再定位任一侧匹配的决策。仅使用 `coverage.members`，并以 `computed_at` 限定记录时间，后续对局和截止时间之后的决策不得混入。
- 明确区分原场景表保存的运行整体格式诊断统计与共同有效样本内的记录导航。导航读取当前仍保存的记录，不冒充逐条冻结归档，不改写快照，不重算已保存的统计。
- 展示 A/B 决策记录数、涉及对局数、任一侧有记录的同源对局组数。允许单侧匹配；组内记录相关、对局跨场景重叠，不能把计数当独立样本或能力比较。
- 分类筛选只提供定位：先对完整序列判定路径，再标明左右场景，提供前后匹配步骤入口。完整时间线和缺失占位保留，不压缩步骤、不把两侧分别筛选后的序列重新配对。
- 从格式诊断表进入相应场景；完整决策页返回时保留快照、场景、发牌及原步骤，并继续保留既有报告来源。刷新、桌面地址保存、快速切换和重试使用同一位置约定。
- 指定发牌或步骤缺失、地址非法、对局身份变化或记录缺失导致无匹配时，明确提示，不默认改选另一份证据。记录中重复轮次保持无法确认，不自动挑选。

## 设计与实现

沿用 Ink Lab 编辑式布局：比较摘要在上、已有证据工作区在下，场景筛选与计数放在同源对局选择器之前，详细定义按需展开。继续使用 IBM Plex Sans / Noto Sans SC 和既有主题令牌（浅色背景 #f5f5f7、表面 #ffffff、正文 #1d1d1f、强调 #1a6b5c）；保留暗色模式与窄屏双侧转单列，不新增视觉体系。

扩展现有 pairs 与 pair 只读 API，使用可选 scenario 参数。仓库按规范 SQL 汇总冻结成员及截止时间内的当前记录；服务在同一读事务验证游戏身份。完整序列仍由唯一 `align_decisions` 判断路径，场景标记不参与可比性判断。前端复用 ComparisonReplay、DecisionPreview、既有草稿引用和完整决策页，不增加回放或持久化实现。

## 检查与边界

测试冻结成员/截止时间、单侧匹配、计数分母、空组、变化/删除、缺口后不可恢复同一路径、地址与返回位置和迟到请求。浏览器使用隔离合成记录验证从场景表至决策往返，运行相关质量检查。

本批不新增因果推断、场景胜率或模型排名，不调用模型或评估器。完整牌桌重建、任意场景针对性测试及发布验收仍属后续。
