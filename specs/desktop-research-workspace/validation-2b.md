## 交付边界

- 当前向导要求完整冻结、固定发牌、无跨局记忆、至少一个模型选手的斗地主基线。不完整协议明确拒绝，不自动转换；离线策略不使用提示词，不能冒充 Prompt A/B。
- 模板版本复用已有提示词管理；本批没有新增另一套模板编辑器。选中的持久化版本会独立冻结，不要求它是活动版本。
- 向导输入尚未接入持久草稿；有离开/刷新保护和失败保留输入，但不能承诺强制关闭后的恢复。已创建运行的笔记和比较结论继续使用共享草稿服务。
- 向导初验仅覆盖设计流程。后续的[本地模型实局验收](#本地模型实局验收)记录了模型响应、规则接管和配对结果；独立用户试用另列于[分批实施计划](tasks.md)。
- 继续复用同一 Vue/Python 业务实现；不新增历史协议转换、双写或第二套采集/比较/结论逻辑。

## 本地模型实局验收

2026-11-05，在隔离的 Windows 工作区通过打包后端完成本地 Qwen2.5-0.5B 微调模型的四局采集。A 使用冻结的出牌提示词，B 增加「跟牌时，如果有多个同牌型、同张数的合法出牌都能压过上一手，优先选择其中能压过的最小点数。」观察模型席位所在阵营的胜率。其余两席分别使用启发式与首个合法动作策略。两组共用同一份 Q4_K_M 权重、席位顺序和调试牌，温度 0，输出上限 192 token，关闭跨局记忆。按 A1、B1、B2、A2 顺序采集。

| 调试牌种子 | 两组中模型的身份 | A 的胜方 | B 的胜方 |
|---|---|---|---|
| 100001 | 农民 | 农民 | 农民 |
| 100002 | 农民 | 地主 | 地主 |

计划 2 对，有效 2 对，排除 0 对。模型所在阵营两组均胜 1 对，仅 A 胜 0 对，仅 B 胜 0 对，均负 1 对。胜率差 B − A 为 0 个百分点，保守 95% 区间为 −88.82 至 +88.82 个百分点，双侧精确 McNemar p = 1。本批没有使用独立验证牌，无法据此判断提示词能提高胜率。

- **实际推理。** 本地 Ollama 的 CPU 推理共完成 53 次对话请求，包含重试。模型选择的合法动作 A 为 25/26，B 为 25/25。A 有一次由规则接管，计入整局胜负。在模型实际作答且有多个不同点数可压的跟牌机会中，选择最低可压点数的次数为 A 组 2/9、B 组 3/8。机会来自各自走到的局面，仅作描述。
- **输入与标注。** 按实际发送的系统消息核对，新增指令在 A 的 26 次出牌中出现 0 次，在 B 的 25 次中出现 25 次。B 的 18 条残局轨迹把版本写成了基线版。已统一模板正文与轨迹版本的选取，并保留原始记录供复查。
- **故障与样本。** 第一次诊断中 Ollama 目录列出标签，对话端点却返回 404，原实现仍重试并用规则继续对局。第二次诊断中 Vulkan 推理进程反复退出。正式采集在新的独立目录以 CPU 执行，两次诊断均排除在这份设计的样本之外。Ollama 的 404 现在沿用统一的供应商错误分类，流式和普通调用都直接终止当前对局。
- **证据与试用。** 已保存带两条原始决策引用的结论，从产品接口导出 JSON，重启后读回核对。研究数据、权重散列和报告保存在本机。另备有仅含基线和候选模板的试用起点，以及可单独打开的结果副本。独立使用体验待未参与开发的人实际试用。
