# 第三批 A：同源对局与决策对照

日期：2026-11-03。承接已批准的证据工作区方向，本批交付共同样本 → 同源对局 → 决策序列 → 引用观察，不增加新的研究或存储体系。

## 验收条件

1. 当打开双组斗地主比较快照时，只列出快照冻结的共同有效发牌成员；后续对局不得进入该列表。
2. 当选择一副牌时，并排展示 A/B 的记录，前后步、首次分歧入口与时间线共同驱动两侧；切换牌局时清除旧画面，迟到请求不得覆盖新选择。
3. 当两侧从第 0 步起记录连续、席位及记录局面一致、此前动作一致时，标记为记录一致；本步动作不同标记为首次行动分歧。分歧后的步骤保持不同路径，不再暗示相同局面。
4. 当记录缺失、重复、解析回退、动作与所存菜单不一致或上下文不足时，明确标记无法确认；不能跳过缺口恢复“同一路径”。记录轮次只作为序列位置，不单独构成可比依据。
5. 当游戏已删除、种子/席位/所属运行与快照不符或冻结引擎条件不同，拒绝对照并保留解释；不猜测、不重配对，不添加旧协议转换。
6. 当引用当前对照时，将可用的两侧决策加入既有研究草稿；不重复引用，最多 30 条，超过上限不部分写入。记录仍需明确操作才发布为正式结论。

## 结构与边界

- 范围以 `coverage.members` 为唯一依据，同时收紧现有候选查询与结论引用范围；不再用所有运行对局冒充共同有效样本。
- API → ResearchMixin → Repository/Core：仓库负责按快照截止时间读取，Core 负责无 I/O 的记录对齐，服务验证对局身份。请求不执行模型、评估器或重新采集。
- 对齐使用记录的席位、阶段、本人手牌、对手剩余张数、上一动作、展示菜单和动作序列。玩家 ID 按冻结席位归一；动作 ID 保留叫分等语义，不仅比较牌面。结果明确称为“记录局面对照”，不宣称完整模型输入或心理过程相同，也不重建隐藏手牌。
- 双组用紧凑对局选择器、共享步数控制、并排动作和按需手牌；缺失状态保留占位，单边记录不能冒充另一侧。多组继续使用单次决策审查，不套用双组算法。
- 复用卡牌、动作翻译、侧面板、SQLite 草稿和结论版本服务。没有新兼容路径或第二套回放引擎。
