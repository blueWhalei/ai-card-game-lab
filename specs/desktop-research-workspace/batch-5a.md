# 第五批 A：退出前保存与多窗口关闭保护

日期：2026-11-03。此前桌面宿主在用户确认后直接停止后端；本批已补齐 R6 的原生关闭缺口，落实 R3、R10。分析工作区后续任务保持原计划。实际结果与边界见 [验收记录](validation-5a.md)。

## 验收条件

1. 关闭主窗口时，宿主先向所有研究窗口请求准备关闭，各窗口锁定编辑并调用同一个草稿 store 的 `flushAll`。只有全部窗口确认完成，才显示停止服务与中断任务的退出确认。
2. 保存失败、冲突、未完成的 Prompt A/B 设计或窗口未响应时，退出取消，后端继续运行，输入保留；界面说明原因。不得自动覆盖冲突或用超时代表保存成功。
3. 取消关闭时所有参与窗口恢复使用；连续点击关闭不产生重叠流程，迟到回复不能完成下一次关闭。
4. 关闭证据窗口只保存并关闭该窗口，不停止主窗口或研究服务；主窗口退出则必须覆盖所有证据窗口。
5. 等待期间不允许新建证据窗口或导航到新的编辑现场。未加载工作台的启动页没有草稿，仍提供原生退出确认。
6. 原生权限只向本次后端的精确回环源和研究窗口授予关闭回复/取消及事件订阅能力；网页开发不获得系统权限。不新增通用文件、shell、进程控制或前端退出命令。

## 实现边界

- Rust 使用独立、可测试的关闭协调状态机：递增请求ID、窗口成员、等待/确认阶段。命令从调用窗口获取身份，拒绝过期或非成员回复。45秒未完成准备则取消退出；最终用户确认不按超时自动选择。
- Vue 使用唯一桌面生命周期接入点，调用既有 Pinia 草稿持久化；全局弹窗仅在关闭流程出现。成功表示已收到草稿服务确认，不表示正式结论已发布。
- Prompt A/B 未创建设计注册为关闭阻止项，用户返回页面处理；不另建草稿副本或兼容协议。浏览器离开保护继续使用现有机制。
- 关闭协调不包含运行任务恢复、自动预算控制或强制结束保护；确认退出明确说明未完成任务会中断。异常断电或任务管理器强制结束仍无法保证尚未确认的输入保存。
- 原生 IPC 按 [Tauri capabilities](https://tauri.app/security/capabilities/) 注册应用命令权限，运行时按实际端口授予；前端通过官方 API 调用，不访问内部桥接对象。
