# 第四批 D：历史局面测试记录与可读导出

2026-11-08，延续已授权的 R4、R5、R8、R9、R10。

## 验收行为

- 测试集可分页查看已有离线基线及扰动记录，选择某次测试后刷新、浏览来源决策或重开桌面地址均保留该记录。读取不再次执行测试，不自动选取另一个缺失或无效结果。
- 新结果保存测试时的来源摘要、评估参数和完整测试集内容指纹。读取时区分当前来源一致、变化、缺失、无法读取及当时未记录来源；不补写旧记录或将当前问题冒充历史问题。
- 对当前指标版本的历史数据检查身份、结构、分母和数值。损坏或未知版本的记录仍在列表明确标示，不能混入有效结果或显示零值。所有读取限制在指定测试集目录内。
- 复用原有评分，只有用户主动运行才新增结果；完整文件原子发布且不覆盖历史文件。局面数和重复比较数分别展示，未评估仍为空。
- 同一记录可导出可读 HTML 与 JSON，包含测试条件、来源核对时间、结果、局面明细及解释局限。复用既有 HTML 序列化、原生另存为和文件定位；不将测试记录称作已发布研究结论。

## 实现与界面

沿用 API → PuzzleService → Core 文件格式与 IO，不新建结果数据库。`GET /puzzles/packs/{pack_id}/results` 提供固定 20 条分页和失败状态，`GET .../results/{run_id}` 返回一个保存的结果及当前来源核对状态。新写入附加 `pack_snapshot` 和 `pack_fingerprint`；既有 v2 记录无来源摘要时标为未记录。评分指标版本保持不变。

测试页继续使用 Ink Lab 的主题、字号与间距。运行控件下增加历史记录区，详细测试记录复用一个 Vue 组件，页面与 HTML 导出共用正文；来源信息和各局面明细按需展开。主区域仍显示当前测试集，历史正文明确标注测试时来源，二者不混用。URL 使用 `pack_id/result_id/result_page`，来源决策使用 `puzzle_pack/puzzle_result/puzzle_page` 返回。

本批交付历史读取、来源核对与单次测试可读导出。将局面测试作为正式比较结论的引用需要额外定义比较范围和发布规则，保留后续任务；整组场景抽样、其他变体及桌面发布不在本批。

## 检查

覆盖历史读写、禁止重跑、来源变化/删除/未记录、损坏及未知版本、分页、目录限制、原子发布不覆盖；前端覆盖刷新与返回、迟到响应、空/错误结果、中英文和导出正文。执行质量检查与隔离浏览器验收。
