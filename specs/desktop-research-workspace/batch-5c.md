# 第五批 C：桌面 JSON 原生导出

日期：2026-11-05。落实第五批导出文件操作与 R8、R10。沿用现有导出按钮、数据服务、Toast 和系统另存为对话框，不新增界面区域。

## 验收条件

1. 研究结论、比较快照、实验包、选手配置和草稿副本共用一个 JSON 导出入口。桌面调用系统另存为，浏览器仍交由浏览器下载机制处理；这是平台适配，不维护两套导出内容。
2. 仅在原生写入完成后提示已保存。取消不提示成功或错误；失败给出可重试的提示，不回退到浏览器下载或声称文件已保存。
3. 页面只能提交建议文件名和 JSON 内容，不能指定任意目标路径。实际目标由系统对话框选择，限制 JSON 文件；不开放通用文件系统、shell 或外部程序权限。
4. 同时只能有一次原生导出；关闭准备期间不能开始导出，导出期间不能退出或销毁证据窗口。取消或失败必须释放占用，允许继续使用。
5. 写入使用临时文件完成后再替换目标，避免提前截断已存在文件；同步到文件成功后才返回成功。文件扩展名与内容类型一致，过大或非法请求在打开对话框前拒绝。
6. 中英文提示、调用方等待/错误处理、单元测试及原生保存/取消验收同步更新。

## 技术边界

- 宿主仅授予精确研究源的 main/evidence-* 窗口 `save_json_export` 命令；再次校验源，目标路径不接受前端参数。
- 导出内容继续由当前 API、草稿会话或比较快照生成，统一序列化后交给宿主。上限 32 MiB（UTF-8），仅支持 JSON；大型训练数据、可读报告、导出目录定位仍是后续范围。
- 通用原子文件替换由一个内部函数提供，研究位置记录复用该函数；不添加第二套研究数据存储或格式转换。
- 普通浏览器只能确认下载已交付浏览器，不能声称磁盘写入成功。桌面失败不自动转用浏览器路径。
