# 第四批 B：从正式结论设计后续 Prompt 变体

2026-11-07，落实已授权的 R2、R7、R9、R10，延续第四批 A 的报告工作流。

## 验收行为

- 报告提供「设计后续变体」入口，用户从该报告的冻结运行中选择基线；只核对条件，不创建运行、不调用模型。
- 复用现有三步 Prompt A/B 向导。来源结论版本及观察、解释、局限可查阅；新的假设由用户填写，不自动将旧结论改写成已成立的新假设。
- 前往向导、刷新、切换来源时保留明确的基线和来源版本；迟到请求不能把另一个来源的配置写入当前表单。未保存设计继续受既有离开/关闭保护。
- 提交时，在同一写事务内重新核对来源版本、比较成员、当前基线冻结条件、研究归属、提示词指纹与单项变更资格。缺失来源、不属于报告的基线、发生条件变化或留出运行均不得绕过限制。
- 创建 B 后冻结 `protocol.design.source_revision_id`，通过运行条件与后续报告返回来源报告。旧报告、旧结论和已有运行不改变，不增加另一套版本/来源表。
- 已观察数据上的后续设计明确属于探索性工作；继续复用原调试发牌，不称为预注册或独立验证。新设计冻结后仍可使用既有留出发牌流程，来源关系随之保留。保存设计不会启动采集。

## 实现与界面

在原报告操作区增加次要操作和按需展开的基线选择，不改变报告正文与离线导出内容。向导继续使用既有 Ink Lab 编辑式布局、IBM Plex Sans / Noto Sans SC 以及主题颜色（浅色背景 #f5f5f7、表面 #ffffff、正文 #1d1d1f、强调 #1a6b5c）。来源文字按需展开，主区域仍用于新的假设和单阶段变更；窄窗口沿用已有表单换行规则。

现有 `GET /experiments/{id}/prompt-design` 接受可选 `source_revision_id`，返回核对问题与来源结论；`CreatePromptVariantRequest` 增加同名可选字段。只由服务端读取并验证来源，不接受前端提交的来源正文或比较快照。基线匹配核对游戏、席位顺序及完整冻结协议；名称和工作笔记变化不影响条件匹配。既有指纹与固定计划检查继续覆盖创建前并发变更及目标局数。

路径使用 `/research/:id/prompt-ab?baseline=...&source_revision=...`，路由参数只定位设计，不自动提交。新来源标识只保存在新设计中；普通新设计不继承先前设计的来源。

浏览器验收同时校正运行条件中的两处旧展示：关联对照仅提供关联运行入口，不把内部准备阈值呈现为「进行中」或「对局已完成」；提示词版本与哈希按各阶段的冻结模板列出，不用初始的全局版本代替已经修改的阶段。缺失版本明确显示未记录。

## 检查与边界

API 覆盖来源版本锁定、无模型调用、非成员/缺失/修改拒绝、并发变更和留出来源保留；前端检查入口、后续假设、来源切换与迟到响应、刷新定位、错误恢复和创建请求。执行质量检查与隔离浏览器验收。

本批完成从正式结论发起单阶段 Prompt 变体，其他变体类型、从任意场景建立针对性测试、完整场景下钻和安装包发布仍为后续任务。
