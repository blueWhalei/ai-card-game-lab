# 第五批 J 验收记录

日期：2026-11-19。范围见 [batch-5j.md](batch-5j.md)。本批在既有 OpenAI Costs API 适配器上提供明确启用的周期计划，未扩大供应商费用的归属或覆盖范围。

## 实现与口径

- 数据库迁移至 v9，新增计划版本、运行状态和调度检查时间；既有费用快照、金额精度及人工登记保持不变。旧同步标记为手动触发，不自动为现有研究启用计划。
- 周期计划绑定费用配置版本，保存间隔和原因。修改费用配置后必须重新确认计划；暂停计划不关闭预算检查、不取消已接受任务，也不删除既有快照。计划变更采用版本冲突检查，冲突时保留页面输入。
- HTTP/桌面后端生命周期内每 30 秒检查到期计划，每进程最多两个同步任务。持久化到期时间，恢复服务后只处理当前到期请求，不补发停机期间每个遗漏周期；手动与自动请求通过同一数据库事务占用，避免同一研究和配置重复请求。
- 网络、限流、远端故障及中断逐次延后重试，间隔上限 24 小时。凭据、查询周期或响应校验问题等待处理，手动成功或明确保存计划才恢复。失败和旧请求的迟到响应不能覆盖后续计划状态或已结束的费用记录。
- 缺失、失败、中断、过期或达到上限的供应商快照仍阻止新受控任务。失败后的重试过程不解除限制，同步成功但仍超限也不解除限制。暂停周期计划不会绕过服务端检查。
- 中英文页面区分查询起止、快照保存时间、按查询终点计算的快照时限、下一次计划检查与最近调度检查。页面自动读取状态不发起供应商查询；编辑期间停止轮询，防止覆盖输入。同步间隔不是入账周期，调度检查不证明同步成功或服务持续运行。
- 周期查询更新当前配置的成功快照，不重复累加历史快照，不与人工登记相加，不由 Token 推算完整成本。费用来源仍仅限选定组织、项目与 UTC 区间的接口记录。

## 隔离浏览器验收

使用 `output/billing-schedule-20261119/browser_host.py`、本地端口 18780 与独立 `browser-data/db/app.db`。组织、项目、金额和供应商响应均为合成数据，费用客户端已替换为夹具；没有读取真实账单或运行真实模型、训练。

1. 默认计划关闭；当前配置无快照时显示「无成功快照」，不显示为零费用。
2. 输入 15 分钟计划后尝试关闭，出现未保存保护；取消关闭保留开关、间隔和原因。明确保存第 1 版计划后，实际生命周期调度自动发起同步，无手动同步动作。
3. 首次周期快照含 21 条合成费用，合计 **2.1000000000021 USD**，与上限 **2 USD** 比较后继续阻止任务。记录显示「周期同步」、关联计划第 1 版和查询 UTC 区间；人工登记 **0.100000 CNY** 独立保留。
4. 一次手动请求模拟网络失败，失败金额为 null，保留原成功快照并继续阻止任务；计划显示连续失败 1 次，下一次检查延至完成时间后 30 分钟（15 分钟的两倍）。
5. 费用项目由 `proj_synthetic` 改为 `proj_synthetic_updated`，形成费用配置第 2 版；旧计划显示「费用配置已变更，需重新确认计划」，新配置无快照且限制继续生效。
6. 明确保存绑定配置第 2 版的计划第 2 版后，生命周期调度自动同步新项目；成功金额仍为 **2.1000000000021 USD**，没有与旧快照累加，预算仍超限。
7. 保存计划第 3 版暂停后，页面显示暂停，原成功快照和预算开关保留。从运行页面提交采集被服务端拒绝，提示费用快照达到上限；隔离数据库核对 **新增牌局 0 局**。
8. 英文 720×900 窄窗口中，计划状态、覆盖边界、来源与预算信息可读；对话框 clientWidth / scrollWidth 均为 **703**，无横向溢出。结束后恢复默认视口和中文。
9. 切换至另一未配置研究，显示未设置查询范围、无成功快照及尚未启用计划，不残留原研究金额；最终浏览器无 error/warn 诊断。

数据库复核保留三次同步（周期成功、手动失败、新配置周期成功）及三版计划，最终计划暂停、下次执行时间为空。复核结果为 `browser-verification.json`；截图包括 `periodic-paused-zh.jpg` 和 `periodic-narrow-en.jpg`。测试服务及其启动进程均已关闭，保留合成数据供复核。

## 边界与后续

周期同步只在后端服务运行时执行，关闭服务或电脑休眠期间不执行。调度检查时间和快照时限不保证供应商费用及时、完整入账；间隔限制只为同步留出时间，不构成覆盖完整性证明。

尚未配置和核对真实组织账单，仍需验证部署凭据权限、项目归属及官方费用结果与账单的对应关系。其他供应商、应用关闭后的独立调度、完整成本归属与对账、未来费用预留和实际支出硬上限仍未交付。接口空结果也不能证明实际支出为零。

当前限制针对本研究新的受控任务，不预留在途费用、不停止已接受调用；供应商入账延迟和并行调用仍可能导致实际支出超过预算。上述软件测试不能推出完整费用覆盖、研究效果或财务对账结论。
