# 桌面研究工作室需求

状态：方向及持续实施已由维护者授权。各批次实际交付范围见 [实施计划](tasks.md) 与对应验收记录。2026-11-05。

## 目标与用户

CardLab 帮助本地用户提出卡牌智能体研究问题、组织实验、理解差异、审查证据并保存可追溯的判断。主要用户是模型与 Prompt 开发者、研究者及希望探索智能体行为的个人用户。桌面端是主要产品入口；Vue 与 Python 继续作为唯一界面和研究业务实现。

成功标准是用户能独立完成研究任务，并准确理解结果的适用范围。安装成功、页面美观、指标数量都不能替代这一标准。

## 需求与验收

| 编号 | 用户需要 | 可验收行为 |
| --- | --- | --- |
| R1 | 快速获得第一次价值 | 当用户选择体验基线时，系统应提供明确标注的预设选手和实验条件；确认后才运行，无需模型密钥。示例与真实运行必须区分。 |
| R2 | 先设计有效比较 | 当用户创建研究时，应先选择问题、变更项和主要指标；对照共享条件在启动前检查，模型调用需明确确认。高级参数按需展开。 |
| R3 | 放心运行 | 运行时应显示排队、进行、失败、中断与有效样本；停止含义明确；不得将未完成任务描述为可无损续跑。 |
| R4 | 从发现进入证据 | 分析应支持从总体差异进入场景、对局与决策，并保持研究范围、筛选和返回位置。片段必须提供上下文和筛选依据。 |
| R5 | 正确理解结果 | 当配对差值区间跨零、统计证据缺失或协议不成立时，不得显示已支持方向性结论；点估计接近不得描述为等效；固定样本门槛不得承诺还需多少局即可得出结论。 |
| R6 | 工作不会丢失 | 用户修改实验笔记或比较结论草稿后应自动保存到本地数据库；成功状态只能在服务端确认后显示。刷新、关闭重开和桌面随机端口变化不应影响已保存草稿。加载或保存失败、并发冲突应可见且不得覆盖本地输入。 |
| R7 | 笔记与正式结论清楚分工 | 实验中的文字为工作笔记/工作摘要；带快照和冻结证据的研究结论通过显式操作发布新版本。自动保存草稿不得自动发布结论。 |
| R8 | 成果可读、可复查 | 用户应能导出包含问题、条件、指标、证据和局限的可读报告，并保留机器可读导出；完整复现包与阅读报告分别说明范围。 |
| R9 | 持续开展研究 | 多次运行、比较、证据和结论归属同一研究；快速实验自动组织，不能要求先建立多个管理层级。 |
| R10 | 工程与文档一致 | 新结构只保留一套当前实现；删除被替换入口，不增加旧格式转换、旧路由别名或双写。中英文文案、指南、API 文档与测试同步维护。 |

## 交付边界

第一批落实 R5、R6、R7 与相关 R10：修正方向性判断、保护两类编辑草稿、区分工作摘要与正式版本、修正无密钥体验文档。不会在本批宣称已完成研究实体、全新桌面页面、预算控制、原生退出握手或可读报告。

第二批 A 落实研究实体、首页、研究工作区与运行/比较返回路径，详见 [设计](batch-2a.md)。第二批 B 已提供基于冻结基线的单阶段 Prompt A/B 向导，见 [设计](batch-2b.md)。创建实验已支持单局离线预设和显式的模型目录连接检查。独立用户可用性验证与跨场景分析页面仍待完成。

异常断电或强制结束进程可能发生在自动保存请求完成之前。界面须区分“待保存”和“已保存”；普通网页离开时应保护未确认写入的内容。第五批 A 接入 Tauri 正常关闭的多窗口待写入握手，见 [设计](batch-5a.md)；它不能保证系统强制结束或断电时的绝对恢复。

第五批 B 在正常关闭时保存主窗口研究位置，启动后恢复相对地址及允许的定位参数，见 [设计](batch-5b.md)。编辑内容仍使用唯一草稿服务；不将位置恢复描述为任务续跑或未提交表单恢复。
