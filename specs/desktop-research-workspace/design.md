# 桌面研究工作室整体设计

## 产品结构

主流程：选择问题或模板 → 确认比较条件 → 运行 → 查看发现 → 审查证据 → 记录判断 → 创建下一次验证。流程允许循环和并行：运行中可以记笔记，分析后可以继续验证。

研究工作区组织研究问题、运行集合和相关比较记录；比较下继续承载冻结证据和正式结论。一次快速实验自动获得组织上下文，不要求用户依次建立工作区、项目和研究。实验代表一次固定配置的运行。第二批 A 的数据关系与页面边界见 [实施设计](batch-2a.md)；Prompt A/B 的基线、单阶段变更和条件核对见 [第二批 B](batch-2b.md)；同源对局与记录时间线已按 [第三批 A](batch-3a.md) 交付，场景导航已按第三批 B/C、连续记录核对下的双侧牌桌已按第三批 D 交付。单次决策与局面测试直接引用共用第三批 E 的入口。

主要界面分为四种工作场景：

1. **继续研究**：最近工作、正在运行的任务、待审查结果、恢复上次现场。首次提供示例研究、离线基线和连接自有模型。
2. **设计与运行**：选择研究模板、基线和变更项，确认保持不变的条件、主要指标、预算；运行概览支持进入牌桌与查看失败原因。
3. **分析工作区**：左侧发现与片段列表，中间牌桌/时间线/并排比较，右侧当前证据与笔记。原始追踪、训练数据工具按需展开。
4. **研究记录**：过程笔记、证据、比较快照及正式结论版本；导出可读报告。继续验证从这里创建后续变体。

## 视觉与交互方向

目的：让用户理解智能体如何决策，并保持长期研究的连续性。视觉方向为安静的研究工作室，采用编辑式信息层级；扑克牌、座位、行动轨迹和差异是视觉主体。

首批沿用已批准的 Ink Lab 设计系统，不新增并行主题。当前浅色 tokens 为背景 #f5f5f7、表面 #ffffff、正文 #1d1d1f、强调绿 #1a6b5c；深色沿用同一主题系统，不在业务组件中硬编码。字体沿用现有 IBM Plex Sans / Noto Sans SC 字体栈及平台回退，满足 Windows 中文可读性；这是对通用设计技能字体偏好的项目设计系统覆盖。

新工作区以当前任务为主，侧栏保留研究上下文；检查器按需打开，不要求每个状态始终展示三栏。主要动作、状态、错误和键盘焦点都有清晰层级，状态不能仅靠颜色。动效只解释对局推进、选中关系和差异定位，遵循减少动态效果偏好。首次使用不展示技术协议字段，但高级审查仍可访问。

针对页面信息过载，已按 [运行与比较工作区设计](focus-workspace.md) 替换正式页面：运行前聚焦问题与计划，运行中聚焦进度，完成后聚焦结果不确定性与比较入口。比较页显示真实统计及候选决策，动作与牌面随选择更新；完整条件、样本、指标与编辑器按需打开。静态原型已删除；双侧记录共享时间线，并从连续已核对记录重建行动前牌桌。默认行动者视角，研究者完整手牌视角显式切换，不能称为历史模型可见输入。

## 技术边界

- `web/`：唯一工作台和类型化 API 客户端，复用组件、主题与国际化。
- `server/`：唯一实验、评估、比较、草稿和结论服务；保持 API → Service → Repository/Core 分层。
- `desktop/`：进程、窗口、安装与受限系统能力；不实现统计或研究业务。
- 第二批 A 使用独立研究与运行关系表；研究服务只处理组织，不复制现有实验能力。

## 第一批：可信表达与编辑连续性

### 结果判断

继续使用已有共同有效配对集合、冻结协议审查、McNemar 检验和配对差值区间。方向性判断必须同时满足当前质量门槛、有效配对证据、区间严格位于零的一侧、检验 p < 0.05，以及协议审查通过。点估计本身始终可展示；不能满足条件时明确显示“不确定”及原因，不把接近零当作等效检验。

这里的门槛是本地探索性判断规则，不是样本量/功效计算，也不处理反复查看结果或多重比较。后续运行设计应冻结主要指标、计划样本及停止规则。取消“再跑固定数量就足够”的表述。方法背景：[NIST 样本量说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc222.htm)。

### 草稿

两类草稿共用一个存储与编辑机制：`experiment`（假设、笔记、工作摘要、标签）和 `comparison`（观察、解释、局限、引用、发布基准版本）。各自内容由严格模型校验。

SQLite `workspace_drafts` 以类型和对象 ID 为主键，保存修订号、更新时间与内容。API 读取返回空草稿或当前记录；写入使用 expected_revision 乐观并发检查，在事务内拒绝过期写入。对象不存在返回 404，内容不合法返回 422，冲突返回 409。不依赖 localStorage，因此桌面后端随机端口不会隔离草稿。

前端共用 `usePersistentDraft`：加载完成前禁用编辑，去抖保存、串行提交，处理请求期间继续输入。成功回包仅确认当次提交，不能覆盖后续输入。错误时保留输入，提供重试、导出副本和显式重新加载；冲突不能静默覆盖另一窗口内容。路由离开先等待保存，浏览器刷新/关闭时对未确认写入给出保护提示。

笔记轮询只更新业务状态，不重新覆盖已加载的编辑草稿。比较列表刷新不改变草稿的发布基准版本；用户在查看版本后明确采用当前基准。发布仍使用既有追加版本服务，不新增另一套结论实现。自动保存绝不等于发布。

应用实验笔记复用 ExperimentService.update_experiment，携带草稿修订号并在写事务内校验，拒绝旧窗口应用过期草稿。没有新增第二套笔记更新实现。

### 文字对象

现有实验 `conclusion` 字段仅作为工作摘要，统一用户文案；正式研究结论由比较快照下的追加版本承载。保留字段的现有存储职责，不增加字段别名、双写或数据转换。生成文本入口明确称为工作摘要草稿。

## 后续设计约束

证据必须显示当时可见信息，不能把观察者全知视角误称模型输入；模型输出不被当作可靠的心理解释；rollout 分数显示评估方法与局限。片段筛选提供原因和完整样本入口，防止把个例当总体证据。

桌面系统能力按研究任务引入：恢复窗口与选择、打开导出目录、明确的任务退出行为。凭据只交由受限系统存储能力；页面不获得任意 shell 或文件系统权限。

正常关闭已按 [第五批 A](batch-5a.md) 接入原生保存握手：主窗口等待所有研究窗口确认，证据窗口独立关闭；保存失败或未完成设计阻止退出。持久化继续使用唯一草稿服务，任务恢复、窗口现场恢复和强制结束保护仍不在本批范围。

[第五批 B](batch-5b.md) 已增加主窗口研究位置恢复：关闭准备时记录相对路由，启动时复用已有研究、运行、比较与决策地址；不持久化编辑器内容或操作参数。[第五批 E](batch-5e.md) 将主窗口布局加入同一记录，恢复位置、普通大小和最大化状态。证据窗口集合及任务恢复仍待交付。

[第五批 C](batch-5c.md) 已接入现有 JSON 导出的系统另存为与真实写入反馈。导出复用业务内容、关闭协调器和共用文件替换函数；[第五批 D](batch-5d.md) 在同一导出入口提供保存后定位文件。第四批 A/D 已交付研究报告与局面测试的可读 HTML 导出；大型训练数据导出仍按原流程。

## 验证

后端覆盖跨零、缺失配对证据、方向支持、协议不匹配；草稿覆盖重新连接读取、并发冲突、类型校验与对象隔离。前端覆盖轮询保护、重挂载恢复、保存中继续输入、保存失败和离开保护。运行完整项目质量检查及浏览器交互测试；桌面打包验收单独记录，不将源码测试冒充安装包验证。

本批实际验证结果见 [第一批验收记录](validation.md)。

第二批 C 清除旧分析路由别名及全历史提示词版本比较，内部导航直接使用正式工作区。调用记录统计明示时间范围、截断数、有效分母和未知状态，作为运行诊断；不将调用数当作独立样本。详见 [入口与统计范围](batch-2c.md)。
