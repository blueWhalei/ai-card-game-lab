## 真实浏览器流程

使用 Playwright CLI 操作 Chromium。后端仅监听本机，SQLite 与数据目录为仓库忽略的 `data/focus-implementation/`，环境文件指向该测试目录的空配置位置。所有新建选手均为 heuristic 离线策略，未调用真实模型或更改用户研究数据库。现有演示冒烟也使用同一隔离服务。

1. 通过正式 API 创建 A/B 同源固定发牌运行，各两局。运行前显示问题、计划与开始动作。打开条件面板后 Escape 关闭，焦点回到入口。
2. 点击开始仅出现批次数量与用量说明，采集请求数为 0；确认后请求数为 1。两轮均正常结束，比较得到 2 组共同有效样本。样本偏少的提示保持可见，0 差值不被解释为等效。
3. 另建单局离线运行验证运行中进度、对局明细、全部暂停与全部继续；恢复后让任务完成。检查结束列表不会在运行中尚无结果时提示再次开局。
4. 保存比较快照后显示真实候选决策。切换决策同步更新选择、动作与实际牌面，长编号按需展开；打开决策现场保留 game_id、decision_id、comparison_id。
5. 引用决策并填写观察，关闭与重开编辑面板后保留；刷新页面后从数据库恢复同一草稿。未发布正式研究结论。
6. 完整指标面板包含 P95 等次要指标，390px 窗口仍可访问；页面无横向溢出。侧面板中的 Tab 保持焦点约束，Escape 关闭后返回入口。
7. 检查 1440 × 1000、390 × 844、浅色、深色、英文及减少动态效果设置。比较页只保留一个主标题，窄屏标题显示实验对比。最终刷新及主要导航未捕获 pageerror。

先前分步验证暂停时，离线局已结束，故改用一次连续操作新建、启动、暂停与恢复，完整流程通过。开发期的面板定位等待也受热更新影响，最终检查在页面稳定后完成；不将定位超时当作产品行为通过。
